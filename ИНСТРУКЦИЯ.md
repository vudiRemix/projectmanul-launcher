# Инструкция администратора Project Manul

Пошагово, с нуля: как выпускать сборку, обновлять лаунчер, писать новости и настроить сервер.
Всё делается на Windows. Команды вводятся в **PowerShell** (Пуск → «PowerShell»).

**Кто за что отвечает.** Репозиторий принадлежит `vudiRemix`, ты в нём соавтор. Сервер, сборка и
выпуск обновлений — на тебе.

---

## Часть 1. Подготовка — один раз

### 1.1. Принять приглашение в репозиторий

Тебе придёт письмо от GitHub «invited you to collaborate on vudiRemix/projectmanul-launcher».
Нажми **Accept invitation**. Без этого выпускать сборки не получится.

### 1.2. Поставить программы

1. **Node.js** — https://nodejs.org → кнопка **LTS** → установить, все галочки по умолчанию.
2. **Git** — https://git-scm.com/download/win → установить, всё по умолчанию.
3. Закрой и заново открой PowerShell, проверь:

```powershell
node --version
```

```powershell
git --version
```

Обе команды должны показать номер версии. Node — 20 или новее.

### 1.3. Скачать проект

Выбери папку, например `C:\ProjectManul`:

```powershell
mkdir C:\ProjectManul
```

```powershell
cd C:\ProjectManul
```

```powershell
git clone https://github.com/vudiRemix/projectmanul-launcher.git
```

```powershell
cd projectmanul-launcher
```

```powershell
npm install
```

```powershell
node node_modules/electron/install.js
```

Дальше **все команды выполняются в папке** `C:\ProjectManul\projectmanul-launcher`. Если открыл новое
окно PowerShell — сначала `cd C:\ProjectManul\projectmanul-launcher`.

### 1.4. Положить ключ подписи

Ключ `manifest-private.pem` тебе передадут отдельно. Это **главный секрет проекта**: кто им владеет,
тот может выпустить «сборку» для всех игроков.

1. Создай папку `keys` в папке проекта и положи туда файл. Должно получиться:
   `C:\ProjectManul\projectmanul-launcher\keys\manifest-private.pem`
2. Проверь:

```powershell
npm run check-key
```

Должно быть: «Ключ верный». Ключ **никогда** не выкладывай на GitHub, в Discord и т.п. (папка `keys`
уже исключена из репозитория). Храни копию на флешке.

### 1.5. Создать токен GitHub

Токен — это пароль для скрипта, чтобы он мог загружать релизы.

1. GitHub → аватар справа вверху → **Settings** → слева внизу **Developer settings**.
2. **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**.
3. Note: `projectmanul release`, Expiration: на свой выбор (например, 90 дней).
4. Галочка **public_repo** (больше ничего не нужно) → **Generate token**.
5. Скопируй токен (`ghp_...`) и сохрани в менеджере паролей — GitHub покажет его один раз.

### 1.6. Настроить публикацию

1. Скопируй пример настроек:

```powershell
copy publish.config.example.json publish.config.json
```

2. Открой `publish.config.json` в Блокноте и поправь:

| Поле | Что вписать |
| --- | --- |
| `source` | папка готового клиента, где лежат `mods`, `config` и т.д. Слэши — прямые: `C:/ProjectManul/client` |
| `include` | какие папки/файлы клиента входят в сборку. Лишнее убери, нужное добавь |
| `forge` | **точно та же** версия Forge, что у сервера (Arclight пишет её в логе при старте, вида `47.3.0`) |
| `once` | файлы, которые лаунчер кладёт только при первой установке — игрок потом может менять их под себя |
| `launcher.installer` | путь к установщику лаунчера (см. 1.7) |

Пример `include`: `"mods", "config", "defaultconfigs", "resourcepacks", "tacz", "options.txt"`.
Папку `tacz` оставь, если есть свои оружейные паки TACZ. Шейдеры (`shaderpacks`) не добавляй — их
игроки ставят сами.

`publish.config.json` — твой личный файл, в репозиторий он не попадает.

### 1.7. Собрать установщик лаунчера

```powershell
npm run dist
```

Через пару минут появится `dist\Project Manul Launcher Setup 1.0.0.exe`. Его путь уже стоит в
`publish.config.json` → `launcher.installer`.

## Часть 2. Сервер — один раз

Готовые файлы лежат в репозитории, в папке `server\prebuilt`.

### 2.1. Проверка ника (NickCheck)

Лаунчер спрашивает у этого плагина, занят ли ник, и предупреждает игрока.

1. `server\prebuilt\NickCheck-1.0.0.jar` → в папку `plugins` сервера (рядом с AuthMe).
2. Перезапусти сервер. Появится `plugins\NickCheck\config.yml`, порт по умолчанию **8765**.
3. Проверь в браузере на самом сервере: `http://localhost:8765/nick/ТвойНик` — должно показать
   `{"nick":"...","registered":true}`.

### 2.2. Проверка модов (ModCheck)

Не пускает на сервер с лишними модами (читы, x-ray и т.п.).

1. `server\prebuilt\modcheck-1.0.0.jar` → в папку `mods` сервера. Игрокам его ставить не нужно.
2. Перезапусти сервер. Появится `config\modcheck-server.toml`.
3. Зайди на сервер с клиента из сборки. Если тебя кикнуло со списком модов — это клиентские моды
   сборки, которых нет на сервере (миникарта, Oculus и т.п.). Впиши их id в `allowedClientMods`:

```toml
allowedClientMods = ["oculus", "xaerominimap"]
```

   и перезапусти сервер. Список id видно в тексте кика и в логе сервера (`[ModCheck] ... лишние моды: ...`).

### 2.3. Адрес сервера для лаунчера

На GitHub открой файл `release-repo/config.json` → значок карандаша (Edit) → поправь → **Commit changes**.

```json
{
  "server": { "host": "АДРЕС-СЕРВЕРА", "port": 25565 },
  "nickCheckUrl": "http://АДРЕС-СЕРВЕРА:8765/nick/{nick}",
  "maintenance": { "enabled": false, "message": { "ru": "...", "en": "..." } }
}
```

Пока сервер не открыт в интернет, там `localhost` — так игра подключается только на том же ПК.
Когда будет внешний адрес (белый IP, домен или туннель вроде playit.gg), впиши его и **открой наружу
оба порта**: игры (25565) и проверки ника (8765). Лаунчеры подхватят изменение примерно за 5 минут.

## Часть 3. Выпуск сборки — каждое обновление

1. Обнови клиент в папке `source` как обычно (моды, конфиги).
2. Открой PowerShell в папке проекта и вставь токен:

```powershell
cd C:\ProjectManul\projectmanul-launcher
```

```powershell
$env:GITHUB_TOKEN = "ghp_твой_токен"
```

3. Сначала прогон без загрузки — покажет, какие файлы новые:

```powershell
npm run release -- --dry-run
```

4. Если всё правильно — выпуск:

```powershell
npm run release -- --notes "Что изменилось в этой версии"
```

Скрипт загрузит только новые и изменённые файлы, подпишет сборку и опубликует релиз. Игроки получат
обновление при следующем нажатии «Играть». Если что-то сорвалось — скрипт сам удалит черновик,
игроки ничего не получат; просто запусти ещё раз.

**Первый выпуск** загрузит всю сборку целиком (сотни МБ) — это нормально, дальше только изменения.

### Ссылка на лаунчер для игроков

```
https://github.com/vudiRemix/projectmanul-launcher/releases/latest/download/ProjectManul-Setup.exe
```

Ссылка всегда ведёт на свежую версию. При первом запуске Windows может показать «Windows защитила ваш
компьютер» — игрок жмёт «Подробнее» → «Выполнить в любом случае» (у лаунчера нет платного сертификата).

## Часть 4. Новости

На GitHub открой `release-repo/news.json` → карандаш → добавь новость **в начало** списка `items`:

```json
{
  "date": "2026-12-01",
  "tag": { "ru": "Обновление", "en": "Update" },
  "title": { "ru": "Новая карта", "en": "New map" },
  "text": { "ru": "Текст новости", "en": "News text" },
  "image": "https://ссылка-на-картинку.png"
},
```

`image` можно не писать. Между новостями — запятая. Проверить, что JSON без ошибок: https://jsonlint.com.
Новость появится в лаунчерах за ~5 минут, выпускать сборку не нужно.

**Техработы:** в `release-repo/config.json` поставь `"enabled": true` — в лаунчере вместо «В сети»
будет «Техработы» и твой текст.

## Часть 5. Новая версия самого лаунчера

1. Обнови код: `git pull`.
2. В `package.json` подними `"version"`, например `1.0.0` → `1.0.1`.
3. `npm run dist` — появится новый `dist\Project Manul Launcher Setup 1.0.1.exe`.
4. В `publish.config.json` поправь `launcher.version` и `launcher.installer` на новый файл.
5. `npm run release -- --notes "Новая версия лаунчера"`.

Установленные лаунчеры сами скачают и поставят обновление при следующем запуске.

## Если что-то не так

| Что видно | Что делать |
| --- | --- |
| Скрипт: `задайте переменную GITHUB_TOKEN` | выполни `$env:GITHUB_TOKEN = "..."` в том же окне |
| Скрипт: `GitHub ... 401` или `403` | токен истёк или нет галочки `public_repo` — создай новый (1.5); проверь, что принял приглашение (1.1) |
| Скрипт: `приватный ключ не найден` | ключ не в папке `keys` (1.4) |
| Лаунчер у игроков: «Подпись манифеста не сошлась» | сборка подписана не тем ключом — `npm run check-key` |
| Игрока кикает «Лишние моды: ...» | если мод из сборки — добавь id в `allowedClientMods` (2.2); если нет — игрок ставил моды сам, пусть нажмёт «Проверить файлы» в настройках лаунчера |
| Игра вылетает | попроси игрока нажать «Скопировать для поддержки» на вкладке «Логи» и прислать текст |
| Не видно новостей / онлайна | проверь JSON на jsonlint.com; адрес и порты сервера (2.3) |
