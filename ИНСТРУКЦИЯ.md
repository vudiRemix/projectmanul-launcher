# Инструкция администратора Project Manul

Пошагово, с нуля: как выпускать сборку, обновлять лаунчер, писать новости и настроить сервер.
Всё делается на Windows. Команды вводятся в **PowerShell** (Пуск → «PowerShell»).

**Кто за что отвечает.** Репозиторий `DED0KOT/projectmanul-launcher` — твой. Сервер, сборка, ключ
подписи и выпуск обновлений — на тебе.

---

## Часть 1. Подготовка — один раз

### 1.1. Если проект уже скачан

Если ты уже делал `git clone` раньше, просто обнови его (в папке проекта) и переходи к 1.4:

```powershell
git pull
```

### 1.2. Поставить программы

1. **Node.js** — https://nodejs.org → кнопка **LTS** → установить, все галочки по умолчанию.
2. **Git** — https://git-scm.com/download/win → установить, всё по умолчанию.
3. Закрой и заново открой PowerShell, проверь:

```powershell
node --version
```

```powershell
git --version
```

Обе команды должны показать номер версии. Node — 20 или новее.

### 1.3. Скачать проект

Выбери папку, например `C:\ProjectManul`:

```powershell
mkdir C:\ProjectManul
```

```powershell
cd C:\ProjectManul
```

```powershell
git clone https://github.com/DED0KOT/projectmanul-launcher.git
```

```powershell
cd projectmanul-launcher
```

```powershell
npm install
```

```powershell
node node_modules/electron/install.js
```

Дальше **все команды выполняются в папке** `C:\ProjectManul\projectmanul-launcher`. Если открыл новое
окно PowerShell — сначала `cd C:\ProjectManul\projectmanul-launcher`.

### 1.4. Создать свой ключ подписи

Ключ подписи — **главный секрет проекта**: кто им владеет, тот может выпустить «сборку» для всех
игроков. Старый ключ пересылали в чате открытым текстом, поэтому он засвечен и больше не годится —
скрипты откажутся им подписывать. Создай свой:

```powershell
npm run keygen -- --replace
```

(если папки `keys` у тебя нет — то же самое, `--replace` ничему не помешает). Скрипт:
- положит новый ключ в `keys\manifest-private.pem`;
- сам впишет его публичную половину в `launcher.config.json`.

Проверь:

```powershell
npm run check-key
```

Должно быть: «Ключ верный». Теперь отправь изменённый `launcher.config.json` на GitHub. Если git ни
разу не настраивал — сначала две строки со своим ником и почтой GitHub:

```powershell
git config --global user.name "DED0KOT"
```

```powershell
git config --global user.email "твоя@почта"
```

```powershell
git commit -am "Свой ключ подписи"
```

```powershell
git push
```

При первом `git push` откроется окно входа в GitHub — войди в свой аккаунт.

Файл `keys\manifest-private.pem` **никогда** не выкладывай на GitHub, в Discord, в Telegram и т.п.
(папка `keys` уже исключена из репозитория). Сделай копию на флешку: если ключ потеряется, выпускать
сборки, которые примут установленные лаунчеры, будет нечем — игрокам придётся переустанавливать лаунчер.

### 1.5. Создать токен GitHub

Токен — это пароль для скрипта, чтобы он мог загружать релизы.

1. GitHub → аватар справа вверху → **Settings** → слева внизу **Developer settings**.
2. **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**.
3. Note: `projectmanul release`, Expiration: на свой выбор (например, 90 дней).
4. Галочка **public_repo** (больше ничего не нужно) → **Generate token**.
5. Скопируй токен (`ghp_...`) и сохрани в менеджере паролей — GitHub покажет его один раз.

### 1.6. Настроить публикацию

`publish.config.json` — файл, в котором ты один раз говоришь скрипту, откуда брать сборку. Скрипт
берёт из указанной папки моды и конфиги и выкладывает их игрокам. Это твой личный файл, в репозиторий
он не попадает.

**Шаг 1. Сделай «папку клиента»** — в ней лежит ровно то, что должно оказаться у игроков:

1. Создай папку `C:\ProjectManul\client`.
2. Скопируй туда из своего рабочего Майнкрафта со сборкой только нужное:
   - `mods` — все моды сборки;
   - `config` — их настройки;
   - `resourcepacks` — если есть свои ресурспаки;
   - `tacz` — если есть свои оружейные паки TACZ;
   - `options.txt` — если хочешь, чтобы у новых игроков сразу стояли твои настройки игры.

Сохранения, скриншоты, логи и шейдеры не копируй: шейдеры игроки ставят сами.

**Шаг 2. Создай файл настроек:**

```powershell
copy publish.config.example.json publish.config.json
```

```powershell
notepad publish.config.json
```

Внутри будет так:

```json
{
  "repo": "DED0KOT/projectmanul-launcher",
  "source": "C:/ProjectManul/client",
  "include": ["mods", "config", "defaultconfigs", "resourcepacks", "tacz", "options.txt"],
  "exclude": ["**/*.bak", "**/*.disabled", "**/Thumbs.db"],
  "once": ["options.txt", "config/**/*-client.toml"],
  "cleanDirs": ["mods"],
  "minecraft": "1.20.1",
  "forge": "47.3.0",
  "privateKey": "keys/manifest-private.pem",
  "launcher": {
    "installer": "dist/Project Manul Launcher Setup {version}.exe",
    "assetName": "ProjectManul-Setup.exe"
  }
}
```

Поменять нужно максимум три строки, остальное не трогай:

| Строка | Что сделать |
| --- | --- |
| `"source"` | если папка клиента не `C:\ProjectManul\client` — впиши свою, слэши **прямые** `/` |
| `"include"` | убери то, чего нет в папке клиента. Нет папки `tacz` — сотри `"tacz", ` |
| `"forge"` | версия Forge **точно как на сервере**: открой на сервере `logs\latest.log`, найди (Ctrl+F) `Forge mod loading` — рядом будет `version 47.x.x` |

Что делают остальные строки (для понимания):
- `once` — файлы, которые игрок получает один раз и потом может менять под себя (настройки, клавиши);
- `cleanDirs` — в папке `mods` у игроков лаунчер удаляет всё лишнее, так свои моды не поставить;
- `installer` — путь к установщику лаунчера, он появится после 1.7. `{version}` скрипт сам заменит
  на версию из `package.json`.

Частые ошибки: обратные слэши `\` в пути, пропущенные кавычки `"`, лишняя запятая после последнего
элемента списка. Проверить файл можно на https://jsonlint.com.

**Шаг 3. Проверь без загрузки:**

```powershell
npm run release -- --dry-run
```

Скрипт покажет файлы, которые выложил бы. Видишь свои моды и конфиги — всё правильно. Пишет
«ОШИБКА» — текст ошибки подскажет, что не так.

### 1.7. Собрать установщик лаунчера

```powershell
npm run dist
```

Через пару минут появится `dist\Project Manul Launcher Setup 1.0.1.exe` (номер — из `package.json`). Его путь уже стоит в
`publish.config.json` → `launcher.installer`. Собирай **после** 1.4: новый ключ вшивается в лаунчер
при сборке.

**Загрузчик** `bootstrapper\ProjectManul-Install.exe` (52 КБ) уже собран и лежит в репозитории —
его игроки и скачивают. Он в стиле лаунчера: скачивает установщик с GitHub, ставит его без белого
окна Windows и запускает лаунчер. `npm run release` сам выкладывает его в каждый релиз.
**Пересобирать его не нужно**: Windows копит доверие к конкретному файлу, а новая сборка начинает
с нуля. Пересобрать (`npm run bootstrapper`) придётся, только если репозиторий снова переедет.

## Часть 2. Сервер — один раз

Готовые файлы лежат в репозитории, в папке `server\prebuilt`.

### 2.1. Проверка ника (NickCheck)

Лаунчер спрашивает у этого плагина, занят ли ник, и предупреждает игрока.

1. `server\prebuilt\NickCheck-1.0.0.jar` → в папку `plugins` сервера (рядом с AuthMe).
2. Перезапусти сервер. Появится `plugins\NickCheck\config.yml`, порт по умолчанию **8765**.
3. Проверь в браузере на самом сервере: `http://localhost:8765/nick/ТвойНик` — должно показать
   `{"nick":"...","registered":true}`.

### 2.2. Проверка модов (ModCheck)

Не пускает на сервер с лишними модами (читы, x-ray и т.п.).

1. `server\prebuilt\modcheck-1.0.0.jar` → в папку `mods` сервера. Игрокам его ставить не нужно.
2. Перезапусти сервер. Появится `config\modcheck-server.toml`.
3. Зайди на сервер с клиента из сборки. Если тебя кикнуло со списком модов — это клиентские моды
   сборки, которых нет на сервере (миникарта, Oculus и т.п.). Впиши их id в `allowedClientMods`:

```toml
allowedClientMods = ["oculus", "xaerominimap"]
```

   и перезапусти сервер. Список id видно в тексте кика и в логе сервера (`[ModCheck] ... лишние моды: ...`).
   Если кикает с модами вроде `embeddium`, `oculus`, `distanthorizons`, `entity_model_features` — это
   клиентские моды твоей же сборки: впиши их все, иначе кикнет каждого игрока.

4. **Свой текст кика.** В том же `config\modcheck-server.toml` поменяй `kickMessage`, например:

```toml
kickMessage = "ERROR 28#freepink"
```

   Игрок увидит только этот текст. Чтобы ему показывался и список модов, добавь в текст `{mods}`
   (`"ERROR 28#freepink: {mods}"`). Полный список лишних модов в любом случае пишется в лог сервера —
   по коду ошибки ты найдёшь, кого и за что кикнуло. Текст для входа с ванильного клиента —
   `kickVanillaMessage`. После правки перезапусти сервер.

### 2.3. Адрес сервера для лаунчера

На GitHub открой файл `release-repo/config.json` → значок карандаша (Edit) → поправь → **Commit changes**.

```json
{
  "server": { "host": "АДРЕС-СЕРВЕРА", "port": 25565 },
  "nickCheckUrl": "http://АДРЕС-СЕРВЕРА:8765/nick/{nick}",
  "maintenance": { "enabled": false, "message": { "ru": "...", "en": "..." } }
}
```

Пока сервер не открыт в интернет, там `localhost` — так игра подключается только на том же ПК.
Когда будет внешний адрес (белый IP, домен или туннель вроде playit.gg), впиши его и **открой наружу
оба порта**: игры (25565) и проверки ника (8765). Лаунчеры подхватят изменение примерно за 5 минут.

### 2.4. Статус в Discord («Играет в Project Manul»)

Пока лаунчер открыт, у игрока в Discord написано «Играет в **Project Manul** — В лаунчере». Когда он
в игре: «Играет на сервере», время в игре и онлайн сервера, например «Онлайн (12 из 100)». Под статусом
есть кнопки «Скачать лаунчер» и, если укажешь приглашение, «Discord проекта». Сам игрок свои кнопки не
видит, их видят его друзья. Чтобы это заработало, нужно один раз создать приложение в Discord:

1. Открой https://discord.com/developers/applications, войди своим аккаунтом Discord →
   **New Application**. Имя напиши ровно **Project Manul**: именно оно выводится после «Играет в».
2. На странице **General Information** скопируй **Application ID** (длинное число).
3. Слева **Rich Presence** → **Art Assets** → **Add Image(s)**: загрузи логотип (`build/icon.png`,
   квадрат от 512×512) и назови его `logo` → **Save Changes**. Картинка появляется в Discord не сразу,
   а через 10–15 минут.
4. В `release-repo/config.json` (как в 2.3) впиши ID и, если хочешь вторую кнопку, постоянную
   ссылку-приглашение на свой Discord-сервер:

```json
  "discord": {
    "clientId": "ТВОЙ-APPLICATION-ID",
    "image": "logo",
    "inviteUrl": "https://discord.gg/xxxxxxx"
  }
```

Пересобирать лаунчер не нужно: настройка подхватится при следующем запуске лаунчера. Пустой `clientId`
выключает статус. Если у игрока Discord не запущен, лаунчер просто молчит. Игрок может скрыть статус в
самом Discord: Настройки → Конфиденциальность активности.

Это работает в лаунчере **начиная с этой версии**. У тех, кто поставил лаунчер раньше, статус появится
после обновления лаунчера (часть 5).

## Часть 3. Выпуск сборки — каждое обновление

1. Обнови «папку клиента» `C:\ProjectManul\client` (ту, что создал в 1.6 и вписал в `"source"`): положи туда
   новые моды и конфиги, убери ненужные. Именно её содержимое получат игроки.
2. Открой PowerShell в папке проекта и вставь токен:

```powershell
cd C:\ProjectManul\projectmanul-launcher
```

```powershell
$env:GITHUB_TOKEN = "ghp_твой_токен"
```

3. Сначала прогон без загрузки — покажет, какие файлы новые:

```powershell
npm run release -- --dry-run
```

4. Если всё правильно — выпуск:

```powershell
npm run release -- --notes "Что изменилось в этой версии"
```

Скрипт загрузит только новые и изменённые файлы, подпишет сборку и опубликует релиз. Игроки получат
обновление при следующем нажатии «Играть». Если что-то сорвалось — скрипт сам удалит черновик,
игроки ничего не получат; просто запусти ещё раз.

**Первый выпуск** загрузит всю сборку целиком (сотни МБ) — это нормально, дальше только изменения.

### Ссылка на лаунчер для игроков

```
https://github.com/DED0KOT/projectmanul-launcher/releases/latest/download/ProjectManul-Install.exe
```

Ссылка всегда ведёт на свежую версию (заработает после первого выпуска). Игрок скачивает маленький
загрузчик, тот сам скачивает и ставит лаунчер.

**«Windows защитила ваш компьютер».** При первом запуске загрузчика Windows может показать это окно —
игрок жмёт «Подробнее» → «Выполнить в любом случае». Так у всех проектов без платного сертификата
(у MixLand тоже). Положи рядом со ссылкой картинку со стрелкой на «Подробнее». Чтобы со временем окно
пропало, **один раз** после первого выпуска отправь загрузчик в Microsoft:
https://www.microsoft.com/wdsi/filesubmission → «Software developer» → файл
`bootstrapper\ProjectManul-Install.exe` → «Incorrectly detected». Гарантий Microsoft не даёт, но
загрузчик не меняется от выпуска к выпуску, поэтому доверие к нему копится.

## Часть 4. Новости

На GitHub открой `release-repo/news.json` → карандаш → добавь новость **в начало** списка `items`:

```json
{
  "date": "2026-12-01",
  "tag": { "ru": "Обновление", "en": "Update" },
  "title": { "ru": "Новая карта", "en": "New map" },
  "text": { "ru": "Текст новости", "en": "News text" },
  "image": "https://ссылка-на-картинку.png"
},
```

`image` можно не писать. Между новостями — запятая. Проверить, что JSON без ошибок: https://jsonlint.com.
Новость появится в лаунчерах за ~5 минут, выпускать сборку не нужно.

**Техработы:** в `release-repo/config.json` поставь `"enabled": true` — в лаунчере вместо «В сети»
будет «Техработы» и твой текст.

## Часть 5. Новая версия самого лаунчера

1. Обнови код: `git pull`.
2. В `package.json` подними `"version"`, например `1.0.1` → `1.0.2`. Если обновление пришло через
   `git pull` и версию уже подняли за тебя, этот шаг пропусти.
3. `npm run dist` — появится новый `dist\Project Manul Launcher Setup 1.0.2.exe`.
4. В `publish.config.json` в `launcher.installer` должно стоять
   `"dist/Project Manul Launcher Setup {version}.exe"` (с `{version}`, а не с цифрами) и не должно
   быть строки `"version"`. Так нужно один раз; дальше путь подставляется сам.
5. `npm run release -- --notes "Новая версия лаунчера"`. Если установщик не пересобран, скрипт
   откажется выпускать: иначе у игроков обновление шло бы по кругу.

При каждом запуске лаунчер **сначала** показывает маленькое окно «Проверяем обновления…». Если на
GitHub есть версия новее, он прямо в этом окне скачивает её (с полосой прогресса), ставит и
перезапускается уже новым — старая версия у игрока не откроется. Если интернета нет или GitHub не
отвечает 10 секунд, лаунчер просто открывается как есть, чтобы игроки могли играть.

## Часть 6. Внешний вид лаунчера

Весь дизайн — в папке `src\renderer\` плюс иконка:

| Файл | Что в нём |
| --- | --- |
| `src\renderer\styles.css` | **главный файл дизайна**: цвета, шрифты, размеры, рамки, кнопки |
| `src\renderer\index.html` | разметка экранов: вход, главная, настройки, логи |
| `src\renderer\i18n.js` | все надписи на русском и английском |
| `src\renderer\assets\logo.png` | логотип внутри лаунчера |
| `build\icon.png` | иконка программы (256×256): ярлык, панель задач, загрузчик |

Цвета — в самом начале `styles.css` (`--accent: #f5951b;` — оранжевый и т.д.): меняешь в одном месте —
меняется везде. Посмотреть: `npm start`, после правки — `Ctrl+R` в окне лаунчера. Не трогай `id="..."`
в `index.html` (по ним работают кнопки) и папки `src\core`, `src\main` — это логика, не внешний вид.

## Если что-то не так

| Что видно | Что делать |
| --- | --- |
| Скрипт: `задайте переменную GITHUB_TOKEN` | выполни `$env:GITHUB_TOKEN = "..."` в том же окне |
| Скрипт: `GitHub ... 401` или `403` | токен истёк или нет галочки `public_repo` — создай новый (1.5) |
| Скрипт: `приватный ключ не найден` | ключ не в папке `keys` (1.4) |
| Скрипт: `ключ подписи засвечен` | создай свой ключ (1.4) и пересобери установщик (1.7) |
| Скрипт: `ключ в keys/ не подходит` | `launcher.config.json` не от этого ключа — `npm run check-key`; если менял ключ, сделай `git pull` или 1.4 заново |
| Лаунчер у игроков: «Подпись манифеста не сошлась» | сборка подписана не тем ключом — `npm run check-key` |
| Игрока кикает «Лишние моды: ...» | если мод из сборки — добавь id в `allowedClientMods` (2.2); если нет — игрок ставил моды сам, пусть нажмёт «Проверить файлы» в настройках лаунчера |
| Игра вылетает | попроси игрока нажать «Скопировать для поддержки» на вкладке «Логи» и прислать текст |
| Не видно новостей / онлайна | проверь JSON на jsonlint.com; адрес и порты сервера (2.3) |
